# First inventory interaction

Milestone 11 gives each ground bird capacity for **one carried fruit**. A red or blueberry bush is a fruit source because its checked-in object definition uses the `berry_patch` strategy. Mushroom patches remain edible on site through the existing direct meal. This first interaction does not introduce generic stacks, trading, crafting, or a public inventory control.

When a hungry agent reaches an available berry source, it reserves the source through the existing resource-user and waiting queue. Collecting takes one simulation tick. On that tick, `consumeFood` atomically removes one serving from the source and the agent receives `{ kind: 'fruit', sourceId, definitionId, pickedTick }`. A depleted source enters its usual regrowth period; a perishable dynamic source disappears as before. A full inventory blocks another pickup. A waiting agent rechecks availability after the current user releases the resource, so the final serving cannot be collected twice.

While carrying fruit, the default hunger action threshold rises from 0.20 to 0.35. This gives an agent roughly one simulated day to move with the food before eating it at the default need decay rate. When hunger is selected as the most urgent need at or above that threshold, the agent starts an eight-tick `eating_carried` action, restoring hunger at the existing per-tick meal rate. The fruit is removed on completion, and the usual fruit hydration is applied once. The source stock is **not** touched during this meal. Once a carried meal starts, its short action completes without switching goals, so a partially eaten fruit cannot restore hunger repeatedly. Fatal hunger and thirst still apply if the agent reaches their limits first.

Carried fruit does not spoil in this first version. If an agent dies while carrying it, the item is discarded with that agent; no world object is dropped and source stock is not restored. A fruit already taken from a dynamic source remains edible even if that source expires later. These rules keep inventory bounded and avoid a new dropped-object lifecycle. Spoilage and drops can be reconsidered when inventory grows beyond one item.

The item and current action live in the agent's durable snapshot. Old snapshots with empty or absent inventory restore with an empty array; an agent already `eating` directly from a source finishes that saved action. New snapshots reject malformed items, more than one item, and inconsistent carrying actions. No world-config, object-catalogue, or reproduction-policy hash changes are required. Agent detail responses expose the item and action to the read-only web and mobile viewers. Neither viewer can pick up or use items directly.

See the [milestone 11 benchmark](baselines/population-m11.md) for survival, source consumption, carrying time, tick cost, memory, and snapshot growth compared with milestone 10.
