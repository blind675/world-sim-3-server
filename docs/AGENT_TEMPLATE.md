# Agent template and life stages

Milestone 8 introduces one checked-in, validated [ground-bird template](../config/agent-template.json). It describes identity, numeric inherited-trait bounds, and simulated-day thresholds for juvenile, adult, and elder stages. The current animal still uses the established default trait values. Sex and circadian preference remain individual attributes; hunger, thirst, tiredness, memory, route, and current behavior are its changing condition, not species settings.

An agent stores `templateId`, `birthTick`, numeric `lifespanDays`, and the existing individual traits. The lifespan value is chosen deterministically from world seed and ID, so creating or migrating an agent consumes no additional simulation random draws. `age` is whole simulated days and `ageDays` is truncated to a tenth for display; both come from `(currentTick - birthTick) / ticksPerDay`. Stage uses the unrounded age. The birth tick and life stage never depend on server wall time or request timing. Lifespan is prospective only: milestone 8 does not kill agents due to age, change needs or walking, or create offspring.

`GET /api/agent-template` returns the template and its SHA-256 content hash. Agent list, in-view, and detail responses add `templateId`, `species`, `birthTick`, `age`, `ageDays`, `lifeStage`, and `lifespanDays`. These routes are read-only. The web and mobile viewers display the fields in selected-agent details and tolerate an older backend without them.

The template loads and validates before world restoration or timer startup. The snapshot pins its hash. A snapshot written before milestone 8 lacks the hash and per-agent fields; it may restore only with the exact initial template. Migration assigns existing agents `birthTick=0`, consistent with the world having started at tick zero, then derives their current age from the saved tick. It also assigns a deterministic lifespan potential and removes the old static `age:0` field. IDs, coordinates, needs, memories, paths, random state, and behavior remain intact. The next snapshot writes the template hash and new fields. A different template hash fails startup clearly, preserving the saved world for review. New snapshots require valid per-agent age and trait fields.

The template is a deployed code asset, not a live admin editor. A template change for an existing world requires a reviewed migration or an explicit reset. Back up the persistent volume before a `main` release. Reproduction and inheritance come in milestone 9; age-related death and population balance come in milestone 10.
