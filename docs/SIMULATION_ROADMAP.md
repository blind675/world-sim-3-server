# Life Simulation v3 roadmap

**Current milestone:** 11 complete on `staging`; the next milestone is to be planned. A native-device smoke test remains recommended for the mobile viewer. This is the canonical progress tracker for the server, web viewer, and native mobile viewer. The [population plan](POPULATION_PLAN.md) defines the boundaries and acceptance checks for milestones 8–11. The deeper [design draft](SIMULATION_DESIGN_DRAFT.md) records the reasoning and future ideas; the historical PRD and build checklist are not a description of current behavior.

All ordinary work, including roadmap updates, is committed to `staging`. `main` changes only for an explicitly requested release. See [release workflow](RELEASE_WORKFLOW.md). The backend owns world state; web and mobile remain read-only production viewers.

## Milestones

- [x] **1. Native mobile map parity.** Use the existing object catalogue and agent timing/path responses to display recognizable bundled object art, a distinct selected-agent marker, and a wrapped route line. Animate movement between polls without frame-by-frame requests. Native device performance and gestures still need a smoke test.
- [x] **2. Survival baseline.** The offline [baseline report](baselines/README.md) covers three fixed seeds, 50 agents each, and 2,500 ticks. It records water discovery and drinking, lifespan and death causes, travel and idle state, CPU/RSS, and snapshot size. Across seeds, 120/150 agents died of thirst at tick 2,001; use these measurements as regression checks.
- [x] **3. Clock and credible ground-bird survival.** A fictional fruit-eating, flightless bird has a 360-tick day, walking in the proposed 2–5 km range on active days, separate hunger/thirst/tiredness budgets, terrain-water drinking, and rest anywhere. A bounded regional water guide now helps agents without a shoreline memory find water; fatal needs outrank nonfatal tiredness. The [follow-up baseline](baselines/survival-m3-water-guide.md) records all 50 agents in each of three fixed seeds drinking before critical thirst, with zero thirst deaths through 2,500 ticks. Snapshot continuation and deterministic replay checks pass. The [earlier baseline](baselines/survival-m3.md) preserves the failed first run for comparison. Individual mortality remains possible beyond this measured period.
- [x] **4. Habitat and object variety.** Forest mushrooms, shore reeds, and fallen wood have distinct web/mobile art and terrain-filtered deterministic positions. Legacy objects keep their IDs and positions. Regrowth can create one-serving mushroom offspring that rot after 360 ticks, with sparse scheduled expiry restored from snapshots. The [milestone 4 baseline](baselines/survival-m4.md) compares density, survival, tick cost, memory, and snapshot size; an exact previous-catalogue snapshot migrates without resetting the world. Automated checks pass. The artwork was inspected, but live viewer and native-device interaction remain unverified in this cloud environment.
- [x] **5. Interpretable behavior.** A bounded, versioned [behavior catalogue](BEHAVIOR_MODEL.md) schedules ten-tick idle, twenty-tick look-around, weighted exploration, and named survival policies. Each stay/turn advances one tick; existing movement and resource actions retain their authoritative tick phases. Urgent needs interrupt leisure, and the agent's active policy, cooldowns, and PRNG progress resume from snapshots. The backend exposes a read-only catalogue and active behavior; web and mobile agent details display it. The [milestone 5 baseline](baselines/survival-m5.md) records 150/150 agents drinking and surviving through 2,500 ticks with median active-day travel near 2.9 km. Automated checks pass. Browser and native-device interaction still need a live manual check in an environment with working viewer tools.
- [x] **6. Daily rhythm and light.** The saved tick-derived clock now drives preferred sleep windows, diurnal/nocturnal variation, gradual dawn/dusk light, and reduced night vision. Fatigue further shortens vision before it could become dangerous; tiredness remains nonlethal and urgent food or water can interrupt sleep. Existing snapshots gain a deterministic preference without resetting the world. The [milestone 6 baseline](baselines/survival-m6.md) records 150/150 agents drinking and surviving through 2,500 ticks, with walking distance within 0.5% of milestone 5 in each seed. Web and mobile viewers display the new fields; web terrain dims at night. Automated checks pass, while browser and native-device interaction await manual verification.
- [x] **7. Temperature and weather.** A [versioned climate model](CLIMATE_MODEL.md) derives local temperature from time and elevation, then applies seeded daily clear, rain, heatwave, or cold-front weather. Bounded cold/hot metabolism costs and rainy-day vision loss add observable pressure without a stored world grid. A temperature-only checkpoint preceded the weather run. The [milestone 7 baseline](baselines/survival-m7.md) records 150/150 agents drinking and surviving through 2,500 ticks, with walking within 0.8% of milestone 6 across the standard seeds; an extra two-day cold-front run also kept 50/50 alive. Backend and viewer automated checks pass; browser and native-device interaction remain a manual follow-up.
- [x] **8. Agent templates and life stages.** The validated, versioned [ground-bird template](AGENT_TEMPLATE.md) defines identity, inherited-trait bounds, age stages, and prospective lifespan. Age derives from saved ticks. Existing snapshots migrate without resetting agents; a changed template fails startup. Read-only web and mobile details show the fields. [Three-seed measurements](baselines/survival-m8.md) match milestone 7 travel and survival exactly; the primary snapshot gained 2,687 bytes for 50 agents. Automated checks and a local desktop/mobile browser check pass; native-device interaction remains unverified. Age-related death stays disabled until milestone 10.
- [x] **9. Reproduction and inheritance.** The checked-in [reproduction policy](REPRODUCTION_MODEL.md) governs nearby adult pairs, a free walkable birth cell, parental hunger/thirst costs, cooldown, bounded inherited traits, and a 60-agent default cap. Snapshots pin the policy and save parent links, monotonic birth IDs, birth count, and birth PRNG state. Tests cover blocked/successful births, migration, cap, and replay after a birth. The [standard survival run](baselines/survival-m9.md) exactly matches milestone 8 before adulthood; [mature-population runs](baselines/reproduction-m9.md) reached the cap in three seeds without exceeding it. Web/mobile viewers show read-only population or lineage details. A local web browser check passed; native-device interaction and natural 30-day population survival remain unverified. Age-related death stays disabled.
- [x] **10. Lifespan and population balance.** Agents die of `old_age` at their saved lifespan boundary, before needs decay. A 20-to-64-cell partner-radius adjustment produced natural births in three 512-cell seeds by day 61; 6–10 agents survived each 61-day run after 6–9 births and 10–12 hunger deaths. A controlled elder cohort recorded 12 age deaths per seed while newborns survived. Exact milestone 9 policy snapshots migrate without resetting the world, replay tests pass, and no benchmark exceeded the population cap. The [population report](baselines/population-m10.md) records age/trait distributions, travel, memory, tick time, RSS, snapshots, and the reduced-world and 61-day horizon limits. Production-sized long-term stability remains unmeasured.
- [x] **11. First inventory interaction.** A ground bird can collect one fruit from a berry source, carry it for roughly a simulated day, and eat it later. The source loses one serving at pickup, the item and action survive snapshots, and older direct-meal snapshots continue. Mushrooms remain direct meals. Read-only web/mobile details show the item and action. The [inventory model](INVENTORY_MODEL.md) and [three-seed measurement](baselines/population-m11.md) record rules, survival, resource use, tick cost, RSS, and snapshot growth. All automated checks and a local web browser check passed; native-device and live-host verification remain open.

**Mobile selection polish after milestone 1:** a compact agent/object card, persistent map highlight and label, clearer agent details, and optional live food stock are released on `main`. This uses an additive read-only object detail response. Typecheck, tests, and iOS/Android Expo exports passed; tapping, gestures, and frame rate still need a real device or native simulator because this cloud environment has neither.

## Release gates

Each milestone needs relevant automated tests, a manual viewer check when UI changes, and a comparison with the baseline when survival changes. Backend changes must pass snapshot save/restore and deterministic-replay tests. Track CPU, memory, request rate, and snapshot growth for the single-instance deployment.

Snapshots pin the object catalogue and world configuration. For incompatible backend changes, preserve the live world through a tested migration or compatibility path where feasible; back up the snapshot before release. A reset is an explicit last resort, never an automatic fallback. Coordinate releases backend first, web second, mobile third when clients depend on new API fields.

Update the current/next labels and checkboxes only after the milestone's checks pass. Record any validation limits in the commit or release report.
